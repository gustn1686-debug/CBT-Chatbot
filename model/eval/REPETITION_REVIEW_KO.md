# CBT 모델 반복·상담 품질 문제: 팀 논의 메모

작성일: 2026-10-12

이 문서는 `cbt_multiturn_experiments`의 보관 코드, 공개 대화 결과, 집계와 실험 기록을 읽고 정리한 메모다. 새 학습이나 모델 생성 실험은 수행하지 않았다. 실제 학습 원문·가중치가 없으므로 원인을 확정하는 진단은 아니다.

## 먼저 공유할 핵심

현재 문제는 두 가지다.

- **표현 반복:** 같은 문장이나 비슷한 말투가 자주 나온다.
- **진행 반복:** 이미 답을 받았거나 동의를 얻었는데 같은 질문·제안을 다시 한다. 표현이 달라져도 대화가 앞으로 나가지 않는다.

가장 먼저 논의할 가설은 “짧은 문맥과 질문 중심 정답으로 상담 말투는 배웠지만, 이전 합의에 따라 다음 행동으로 넘어가는 능력은 충분히 배우지 못했을 수 있다”는 것이다. 여기에 기본 생성 방식과 프롬프트가 영향을 줄 수 있다. 파인튜닝 전 모델에도 반복이 있어 파인튜닝 하나를 원인으로 단정할 수 없다.

## 1. 실제로 어떤 문제가 보였나?

[E04 original/tuned R002 대화](cbt_multiturn_experiments/experiments/E04_prompt_ablation/results/original_tuned_R002.md)에서:

- 대화쌍 4·5: “이런 생각들이 꽤 광범위하게 퍼져 있는 것 같네요.”를 그대로 반복한다.
- 대화쌍 9: 내담자가 이미 “이번에는 잘하지 못했지만, 훈련을 더 하면 나아질 수 있어”라는 대안 생각을 말한다. 그런데 상담자는 다시 생각을 다르게 바라보는 방법을 찾자고 제안한다.
- 대화쌍 10·11: 비슷한 제안과 동의 확인이 이어지며 구체적인 연습으로 잘 넘어가지 않는다.

기대하는 행동은 예를 들어 “방금 만든 대안 생각을 다음 연습 때 어떻게 적용할지 정해보자”처럼 이미 나온 내용을 활용하는 것이다. 이 예시는 다음 행동의 설명이며 임상적 정답을 확정한 것은 아니다.

[같은 사례의 base 결과](cbt_multiturn_experiments/experiments/E04_prompt_ablation/results/original_base_R002.md)에서도 스스로에게 어떤 말을 하는지 여러 번 묻는다. 여기서 base는 CBT 추가 어댑터를 적용하지 않은 조건이다.

## 2. 가능한 원인과 근거

### A. 학습 예제의 문맥이 제한돼 있다

**코드로 확인한 사실:** [prepare_dataset.py](cbt_multiturn_experiments/code/training_20260923/prepare_dataset.py)의 `--context-pairs` 기본값은 4다(598행). `make_sft_examples`는 정답 직전 `2 * context_pairs - 1`개 발화만 가져온다(434~437행).

기본값이면 다음과 같은 학습 문제가 된다.

```text
과거 대화: 제외
최근 사용자 → 상담자
최근 사용자 → 상담자
최근 사용자 → 상담자
현재 사용자
↓
맞혀야 하는 상담자 답
```

길이 상한을 넘으면 오래된 대화쌍을 추가로 제거한다(455~462행). 별도의 시스템 지침은 포함한다.

**가능한 영향:** 초기 목표, 이미 제안한 연습, 사용자의 동의가 오래전에 나왔다면 입력에서 빠질 수 있다. 다음 답을 학습할 때 필요한 정보가 부족해지고, 전체 상담의 단계 전환보다 최근 말에 반응하는 패턴을 익히기 쉬울 수 있다.

**아직 확인할 것:** 기본값은 실행 옵션으로 바꿀 수 있다. 감사 집계와 기존 기록은 짧은 문맥 구성을 뒷받침하지만, 감사 파일과 실제 학습 입력의 동일성은 당시 해시 부재로 확인되지 않았다. 실제 실행 명령과 처리 데이터의 `configuration.context_pairs`를 확인해야 한다.

**혼동하지 말 것:** [멀티턴 재생 코드](cbt_multiturn_experiments/code/qwen_replay_20261006/generate_replay_diagnostic.py)의 `replay_session`은 사용자 발화와 생성 응답을 계속 이력에 추가한다. 이 경로는 평가 때 최근 3번만 보내는 구조가 아니다. “학습 문맥이 제한됨”과 “평가 이력을 안 보냄”은 다르다.

### B. 정답이 질문형 응답에 치우쳐 있다

**기록에서 확인한 사실:** [학습 데이터 감사 집계](cbt_multiturn_experiments/experiments/E00_training/data_audit_aggregates.json)에서 CACTUS train 정답 11,708개 중 10,701개(91.4%)에 물음표가 있다. 10,566개(90.2%)는 질문으로 끝난다. AIHub의 물음표 포함 비율은 약 50.1%다.

**가능한 영향:** “공감 → 질문”을 자주 학습하면, 사용자가 이미 답하거나 마무리를 원해도 질문을 만드는 방식으로 돌아갈 수 있다. 다만 물음표가 많다는 사실만으로 해당 답변이 잘못됐거나 특정 반복 문구가 학습 원문에서 왔다고 단정할 수 없다.

### C. 생성 기본값이 익숙한 표현을 반복 선택할 수 있다

**코드로 확인한 사실:** 위 재생 코드의 `make_generator`는 기본적으로 sampling을 끄고 `repetition_penalty=1.05`를 사용한다(85~106행). 양수의 응답 온도가 전달되면 sampling을 켤 수 있다. 초기 멀티턴 생성 코드도 `do_sample=False`를 명시한다.

**쉬운 설명:** 가장 확률 높은 다음 토큰만 고르는 방식에서는 비슷한 상황마다 자주 쓰는 표현이 선택될 수 있다. 여기서 높은 확률은 “가장 좋은 상담 행동”을 뜻하지 않는다.

**가능한 영향:** 표현 다양성을 제한할 수 있다. 하지만 같은 제안을 다른 말로 반복하는 문제는 sampling만으로 해결되지 않을 수 있다. 반복 페널티도 상담 단계가 완료됐는지를 판단하는 기능은 아니다.

### D. 프롬프트도 공감·질문 형식을 유도할 수 있다

**확인한 사실:** [기본 프롬프트](cbt_multiturn_experiments/experiments/E04_prompt_ablation/prompts/original.txt)는 감정을 먼저 반영하고, 필요할 때 CBT 질문이나 연습을 제안하며, 한 응답에서 질문은 하나만 하도록 지시한다. 반드시 질문하라는 지시는 아니다.

**가능한 영향:** 모델과 학습 분포에 따라 이 지침을 반복적인 공감·질문 형식으로 구현할 수 있다.

**이미 수행한 비교:** E06 질문 규칙 완화, E07 재동의 방지, E08 전환 예시 추가에서 일부 국소 변화는 있었지만 안정적으로 해결되지는 않았다. E04의 질문 문자열 반복 후보는 기본→v2 지침 변경 시 base 12→5, tuned 1→8이었다(각 조건 35응답). 이는 소수 사례의 문자열 지표이며 전체 상담 품질 점수가 아니다. 프롬프트 효과가 모델 조건에 따라 달랐다는 근거다.

### E. 일부 데이터가 여러 번 학습에 등장한다

**코드·기록에서 확인한 사실:** [train_qlora.py](cbt_multiturn_experiments/code/training_20260923/train_qlora.py)의 `balance_by_source`는 작은 출처를 복원추출해 출처별 예제 수를 맞춘다. 기존 기록상 AIHub 4,163개를 11,708개로 늘려 평균 2.81회 노출했다. 모든 예제가 정확히 같은 횟수로 반복되는 것은 아니다.

**가능한 영향:** 일부 말투나 대응 패턴이 더 강화될 수 있다. 이 사실만으로 과적합이나 반복의 직접 원인이라고 확정할 수 없다.

### F. 계획·진행 메모 기능이 실패한 실험도 있다

**기존 기록의 관찰:** E03에서는 메모 적용이 base 33/35회, tuned 35/35회 실패했다. 하네스는 모델이 만든 계획·메모를 구조화된 형식으로 읽다가 실패하면 대체 처리를 한다.

**가능한 영향:** 이미 물어본 것과 다음 행동을 메모로 관리하려던 장치가 제대로 작동하지 않아 개선 효과가 제한됐을 수 있다. 그러나 계획·메모를 끈 E04에서도 반복했으므로 이 기능의 실패만으로 전체 문제를 설명할 수 없다.

## 3. 평가 방식 때문에 조심해서 해석할 부분

후속 실험 상당수는 **고정된 사용자 발화를 순서대로 재생**한다. 새 모델이 어떤 질문을 하든 사용자는 원래 대화의 다음 말을 한다.

예를 들어 모델이 “어떤 활동을 할까요?”라고 물었는데 다음 고정 발화가 “네, 좋아요”이면 질문에 필요한 답을 받지 못한다. 이런 어긋남이 재질문을 유발할 수 있다. 따라서 고정 재생에서 보인 모든 반복을 모델의 능력 부족으로만 해석하면 안 된다. 다만 반응형 내담자를 사용한 초기 실험에서도 반복이 기록돼 있어 고정 재생만의 문제도 아니다.

또한 사용자 대본의 후반 호전 발화는 새 모델의 상담 효과가 아니다. 대부분의 후속 비교는 학습 노출 사례를 활용한 진단이며 독립적인 일반화 평가와 구분해야 한다. 전문가 상담 품질 평가도 완료된 상태가 아니다.

## 4. 내일 팀원에게 확인할 질문

1. **실제 데이터 생성 때 `--context-pairs`를 얼마로 실행했나?** 실행 명령, 처리 데이터 설정, 학습 입력 샘플을 같이 볼 수 있나?
2. **우리가 문제 삼는 현재 모델과 평가 조건이 무엇인가?** 기반 모델, 어댑터/체크포인트, 프롬프트, 생성 설정, 계획·메모 사용 여부를 확정하자. 보관 실험과 현재 서비스 설정은 같다고 가정하지 말자.
3. **학습 정답에 이미 동의한 뒤 바로 연습을 실행하는 예제가 충분한가?** 목표 확인, 실행, 결과 점검, 마무리까지 이어지는 예제를 확인하자.
4. **학습 입력만 보고 정답을 만들 수 있는가?** 잘린 앞 대화나 제외한 문진 정보를 알아야 하는 정답이 있는지 확인하자.
5. **체크포인트를 무엇으로 골랐나?** 코드는 학습 중 평가를 끄고 마지막 어댑터를 저장한 뒤 최종 loss를 평가한다. 별도로 멀티턴 품질을 보고 고른 과정이 있었는지 확인하자. 낮은 정답 예측 loss만으로 상담 진행 능력을 판단하기는 어렵다.
6. **실제 질문에 반응하는 평가에서도 같은 문제가 재현되는가?** 고정 대본에서만 생긴 어긋남과 구분하자.

## 5. 원인을 좁히는 다음 비교 순서

한꺼번에 모든 설정을 바꾸면 무엇이 효과가 있었는지 알기 어렵다. 아래는 아직 실행하지 않은 제안이다.

1. 반복 직전의 **동일한 전체 대화 이력**을 고정하고, CBT 어댑터 적용/미적용을 비교한다. 자유롭게 이어가는 대화는 모델마다 이전 응답이 달라져 직접 비교가 어려워진다.
2. 모델과 입력을 그대로 두고 greedy와 sampling을 비교한다. 표현 반복이 줄어드는지와 다음 단계로 넘어가는지를 따로 본다.
3. 같은 조건에서 최소 역할 지침과 기존 CBT 지침을 비교한다. 지침이 반복에 미치는 영향을 본다.
4. 그래도 진행이 정체되면 최근 문맥과 전체/요약 문맥을 사용하는 학습을 비교한다. 문맥을 늘릴 때 정답과 길이 제한도 함께 확인한다.
5. 실제 질문에 답하는 대화로 검증하고, 학습에 쓰지 않은 사례에서도 확인한다.

점검 항목은 “같은 문장 반복”, “이미 답한 질문 재질문”, “동의 뒤 실행 여부”, “대안 생각 활용”, “마무리 요청 반영”으로 나누면 좋다. 표현이 다양해졌다는 이유만으로 상담이 개선됐다고 판단하지 않는다.

## 회의에서 이렇게 말하면 된다

> 결과를 보니 같은 문구도 반복하지만, 이미 동의하거나 새로운 생각을 말한 뒤에도 같은 제안으로 돌아가는 게 더 큰 문제 같아요. 보관 코드에서는 학습 예제를 최근 몇 번의 대화로 잘라 만들고, 질문형 정답이 많으며, 평가 기본값은 greedy예요. 다만 원본 모델도 반복해서 파인튜닝 하나의 문제라고 보기는 어려워요. 실제 학습 문맥 설정을 먼저 확인하고, 같은 대화 이력에서 어댑터와 생성 방식의 영향을 각각 비교해보면 좋겠어요.
